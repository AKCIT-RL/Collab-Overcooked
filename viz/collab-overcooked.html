5 · Uso

Como rodar

# .env na raiz do repo (a chave fica em src/openai_key.txt)
LLM_MODEL=gpt-4o

conda activate collab-overcooked
cd src
python main.py --order boiled_egg                                 # um episódio
python evaluation.py --test_mode fix_task --model gpt-4o --order boiled_egg
cd .. && python3 viz/build_viewer.py && open viz/episode-viewer.html

Para um modelo local, use LLM_MODEL=<nome servido>, LLM_MODEL_DIRNAME= e LLM_BASE_URL=http://host:porta/v1. Nomes com gpt vão para a OpenAI; os demais, para o servidor compatível.

6 · Cuidados

Armadilhas

  • Rode de dentro de src/: prompts e logs são resolvidos a partir do diretório atual.
  • src/openai_key.txt precisa existir, mesmo sem chamadas à OpenAI.
  • request(...) no plan não chega ao parceiro como pedido (só o say chega). Ele fica na fila de quem escreveu e aparece no estado como plano dessa pessoa. No episódio das 17:01, isso fez o Chef esperar 5 ticks por um ovo que já estava no balcão.
  • A métrica de comunicação do evaluation.py chama a API de embeddings da OpenAI.
  • Só existe o layout new_env. O jogo registra fill_dish_with_food(oven0) como put_obj_in_utensil(oven0), o que baixa a similaridade do Chef nos níveis 5 e 6 mesmo num replay perfeito.
  • Pelo akc-harness, o adapter usa o validador e o motion planner do jogo, mas troca o LLM pelo agente do harness: python scripts/overcooked_reference_smoke.py --orders boiled_egg.
